## 2. Tujuan

Dokumen ini berisi kumpulan istilah, definisi, dan singkatan yang berkaitan dengan pengujian perangkat lunak, khususnya pendekatan Keyword-Driven Testing.

Glosarium disusun untuk menyamakan pemahaman anggota tim dalam proses perancangan, dokumentasi, dan pelaksanaan pengujian perangkat lunak.

## 3. Istilah dan Definisi

| No. | Istilah | Definisi |
|---|---|---|
| 1 | Software Testing | Proses evaluasi perangkat lunak untuk menilai apakah sistem memenuhi persyaratan yang ditentukan. |
| 2 | Test Case | Sekumpulan kondisi dan langkah pengujian yang dirancang untuk memverifikasi perilaku atau fungsi tertentu. |
| 3 | Test Data | Data yang digunakan sebagai masukan dalam pelaksanaan pengujian. |
| 4 | Test Execution | Proses menjalankan prosedur atau test case dan mencatat hasilnya. |
| 5 | Test Result | Hasil yang diperoleh dari pelaksanaan aktivitas pengujian. |
| 6 | Keyword-Driven Testing (KDT) | Pendekatan pengujian yang menggunakan keyword untuk merepresentasikan tindakan atau operasi pengujian. |
| 7 | Keyword | Instruksi bernama yang merepresentasikan tindakan tertentu dalam suatu aktivitas pengujian. |
| 8 | Keyword Library | Kumpulan keyword yang dapat digunakan kembali dalam penyusunan dan pelaksanaan pengujian. |
| 9 | Test Automation | Penggunaan perangkat atau skrip untuk menjalankan aktivitas pengujian secara otomatis. |
| 10 | Test Script | Serangkaian instruksi yang digunakan untuk menjalankan aktivitas pengujian. |
| 11 | Expected Result | Hasil yang diharapkan dari pelaksanaan suatu test case. |
| 12 | Actual Result | Hasil nyata yang diperoleh ketika pengujian dijalankan. |
| 13 | Test Environment | Lingkungan perangkat keras, perangkat lunak, konfigurasi, dan jaringan tempat pengujian dilakukan. |
| 14 | Test Procedure | Urutan langkah yang digunakan untuk melaksanakan aktivitas pengujian. |
| 15 | Test Log | Catatan aktivitas, informasi, dan hasil selama proses pengujian. |

## 5. Penerapan dalam Proyek

Dalam proyek Testing & QA Kelompok 4, konsep Keyword-Driven Testing digunakan sebagai pendekatan untuk menyusun aktivitas pengujian secara terstruktur.

Keyword dapat merepresentasikan tindakan pengujian seperti:
- Membuka halaman aplikasi.
- Memasukkan data ke formulir.
- Menekan tombol.
- Memeriksa hasil yang ditampilkan.
- Memvalidasi respons sistem.

Penggunaan keyword yang konsisten diharapkan membantu pemisahan antara rancangan test case dan implementasi teknis otomatisasi pengujian.
